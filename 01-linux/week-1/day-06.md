# День 6 — права доступа в Linux

## Цель

Научиться читать обычные права Unix, менять их для собственных файлов и понимать, почему специальные биты SUID, SGID и sticky bit требуют отдельного внимания при аудите.

## 1. Чтение прав

Команда `ls -l` показывает права в начале строки. Например:

```text
-rwxr-xr-- 1 illidan developers 120 Oct 24 12:00 script.sh
```

Первый символ обозначает тип объекта (`-` — обычный файл, `d` — каталог). Следующие девять символов идут группами по три:

| Кому | Позиции | Значение |
|---|---|---|
| Владелец (user) | 1–3 | права владельца |
| Группа (group) | 4–6 | права участников группы |
| Остальные (others) | 7–9 | права всех остальных |

- `r` — чтение; для каталога позволяет просматривать список имён.
- `w` — запись; для каталога позволяет создавать, удалять и переименовывать записи при наличии также `x`.
- `x` — выполнение файла; для каталога — проход/доступ к объектам внутри.
- `-` означает, что соответствующее право отсутствует.

### Числовая запись

`r = 4`, `w = 2`, `x = 1`. Складываем значения внутри каждой тройки:

| Режим | Владелец | Группа | Остальные | Типичное применение |
|---|---:|---:|---:|---|
| `600` | `rw-` | `---` | `---` | приватный файл владельца |
| `640` | `rw-` | `r--` | `---` | файл, доступный группе только для чтения |
| `644` | `rw-` | `r--` | `r--` | обычный публично читаемый файл |
| `700` | `rwx` | `---` | `---` | приватный каталог владельца |
| `755` | `rwx` | `r-x` | `r-x` | общедоступный для чтения/запуска файл или каталог |

Права каталога и обычного файла работают по-разному: `x` у каталога нужен для доступа к его содержимому. Поэтому режим `644` обычно подходит файлу, но не каталогу.

## 2. Просмотр и изменение прав

```bash
ls -l имя_файла
stat имя_файла
chmod 600 private.txt
chmod u+x script.sh
chmod g-w shared.txt
```

`chmod 600` задаёт полный режим численно. Символьная форма (`u`, `g`, `o`, `a` и `+`, `-`, `=`) меняет выбранные биты и часто удобнее для точечной правки. `chmod +x script.sh` добавляет выполнение всем категориям; чтобы ограничить его владельцем, используй `chmod u+x script.sh`.

Потренируйся только на временном файле в своей домашней папке:

```bash
mkdir -p ~/linux-permissions-lab
cd ~/linux-permissions-lab
touch private.txt script.sh
chmod 600 private.txt
chmod 700 script.sh
ls -l
stat private.txt
```

Не применяй `chmod -R 777` и не меняй права системных каталогов: это открывает данные для записи всем пользователям и может нарушить безопасность или работу системы.

## 3. Владелец и группа

```bash
id
ls -ln имя_файла
chown пользователь имя_файла
chown пользователь:группа имя_файла
```

`chown` меняет владельца (и при необходимости группу); для чужих или системных файлов обычно нужны права администратора. В этой практике ограничься своими файлами. Не меняй владельца `/etc`, `/usr` или других системных путей.

## 4. Специальные биты

- **SUID (`4000`)** — при запуске исполняемого файла его эффективные полномочия могут соответствовать владельцу файла. Для root-owned программы это потенциально привилегированное поведение. Используй его только там, где это предусмотрено штатным пакетом.
- **SGID (`2000`)** — у исполняемого файла влияет на эффективную группу процесса; у каталога новые объекты обычно наследуют группу каталога.
- **Sticky bit (`1000`)** — на общем каталоге ограничивает удаление/переименование объектов их владельцами и администратором. Типичный пример — `/tmp`.

Посмотреть биты можно через `ls -l` и `stat`. Найти SUID-файлы в доступной части файловой системы можно командой:

```bash
find / -type f -perm -4000 -print 2>/dev/null
```

Часть каталогов может быть недоступна обычному пользователю — это ожидаемо. Найденный SUID-файл сам по себе не означает уязвимость: проверь владельца, назначение и пакет, которому он принадлежит. Не удаляй и не меняй его права без понимания последствий.

## 5. Мини-проверка

1. Объясни разницу между `600`, `644` и `755`.
2. Почему `x` важен для каталога?
3. Как добавить выполнение только владельцу?
4. Почему SUID-файл, принадлежащий root, требует внимания?
5. Почему `chmod -R 777 /etc` — плохая идея?

## Краткая шпаргалка

```text
r = 4, w = 2, x = 1
chmod 600 file       # rw-------
chmod 644 file       # rw-r--r--
chmod 755 directory  # rwxr-xr-x
chmod u+x script.sh  # добавить x владельцу
stat file            # подробные метаданные и режим
```
