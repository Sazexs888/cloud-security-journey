# День 7 — повторение недели 1 и аудит файлов

## Цель

Закрепить навигацию, операции с файлами, поиск, перенаправление вывода и права доступа. Практика ниже предназначена для собственной временной папки и не меняет системные файлы.

## 1. Повторение команд

| Задача | Команды |
|---|---|
| Узнать текущую папку и перейти | `pwd`, `cd`, `cd ..`, `cd -` |
| Посмотреть содержимое | `ls -la`, `ls -lh`, `tree` |
| Создать/копировать/переместить | `mkdir`, `touch`, `cp`, `mv` |
| Читать текст | `cat`, `less`, `head`, `tail` |
| Найти текст или посчитать строки | `grep`, `wc`, `sort` |
| Найти файлы | `find`, `file`, `which`, `whereis` |
| Права и метаданные | `ls -l`, `stat`, `chmod`, `umask` |

Помни: `>` перезаписывает файл, а `>>` добавляет данные в конец. Перенаправление `2>/dev/null` скрывает сообщения об ошибках; при диагностике сначала не скрывай их, чтобы понимать, какие каталоги недоступны.

## 2. Безопасная практическая работа

Создай лабораторную папку и несколько тестовых файлов:

```bash
mkdir -p ~/linux-week1-review
cd ~/linux-week1-review
mkdir notes archive
printf 'first line\nsecond line\n' > notes/sample.txt
cp notes/sample.txt archive/sample-copy.txt
find . -type f -name '*.txt' -print
grep -n 'second' notes/sample.txt
wc -l notes/sample.txt
file notes/sample.txt
chmod 640 notes/sample.txt
stat notes/sample.txt
```

Проверь, что понимаешь каждую команду и можешь объяснить, какие файлы она читает или создаёт. Не используй `sudo` для этой лабораторной.

## 3. Аудит без изменения системы

Посмотри права нескольких конфигурационных файлов — только чтение:

```bash
ls -l /etc/passwd /etc/shadow 2>/dev/null
stat /etc/passwd 2>/dev/null
```

Обычному пользователю чтение `/etc/shadow` обычно запрещено — это нормально. Не публикуй содержимое файла: в нём хранятся чувствительные данные аутентификации. Для проверки прав достаточно метаданных `ls -l` или `stat`.

Проверить, какие имена файлов в `/etc` недавно менялись, можно без копирования или редактирования:

```bash
find /etc -type f -mtime -7 -print 2>/dev/null
```

Список зависит от обновлений системы и не является доказательством компрометации. Сравнивай результаты с контекстом системы и пакетными обновлениями.

## 4. `umask` и права по умолчанию

```bash
umask
touch default-file
mkdir default-directory
ls -ld default-file default-directory
```

`umask` ограничивает права, которые могут быть выданы новым файлам и каталогам. Результат зависит от программы, создающей объект, и системных настроек; обычно новые файлы не получают право выполнения автоматически.

## 5. Итог недели

- Могу перемещаться по файловой системе и различать абсолютные и относительные пути.
- Умею создавать, копировать, переименовывать и читать файлы.
- Могу искать файлы и строки, понимать stdout/stderr и перенаправления.
- Читаю режимы `rwx` и использую `chmod` только на объектах, которыми владею.
- Понимаю, почему `sudo`, `rm -rf` и чрезмерно широкие права требуют осторожности.

## Мини-челлендж

В `~/linux-week1-review` создай файл-отчёт, запиши в него список `.txt`-файлов лаборатории, установи права `640`, затем проверь результат командами `ls -l` и `stat`:

```bash
find ~/linux-week1-review -type f -name '*.txt' -print > ~/linux-week1-review/file-list.txt
chmod 640 ~/linux-week1-review/file-list.txt
ls -l ~/linux-week1-review/file-list.txt
stat ~/linux-week1-review/file-list.txt
```

Все команды выше работают только с созданной в домашней папке лабораторией; системные файлы они не меняют.
